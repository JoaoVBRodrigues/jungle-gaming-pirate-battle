# Pirate Battle

Pirate Battle is a browser-based top-down naval shooter built with React, TypeScript, PixiJS, Axios, TanStack Query, MSW, Vitest, and Playwright.

## Setup

```bash
npm install
npm run dev
```

The browser MSW worker is started by `src/main.tsx`, so ranking and match history work in development, preview, and the production build without a private backend.

## Commands

```bash
npm run dev
npm run build
npm run preview
npm run lint
npm test
npm run test:e2e
npm run profile
```

`npm run profile` builds the app, starts a preview server, samples 300 animation frames in Chromium, and prints average FPS, frame-time p95, and available JS heap information.

## Controls

- `W` / `ArrowUp`: move forward.
- `A` / `ArrowLeft`: turn left.
- `D` / `ArrowRight`: turn right.
- `Space`: front fire.
- `Q`: left broadside, three parallel projectiles.
- `E`: right broadside, three parallel projectiles.
- `Escape`: pause or resume.
- Touch controls expose the same movement and fire actions on coarse pointers.

## Gameplay Configuration

Options persist in `localStorage`:

- Game session time: 60-180 seconds.
- Enemy spawn interval: 1-30 seconds.

A match receives an immutable configuration snapshot when Play is selected. Balance values are centralized in `src/game/config/gameConfig.ts`.

## Network Scenarios

Open Ranking or Match History and use the Network scenario selector. Available scenarios are:

- `success`
- `empty`
- `paginated`
- `slow`
- `out-of-order`
- `timeout`
- `server-error`
- `connection-error`

Use Reset Mock Data to restore fixture data. The scenario is persisted in `localStorage`. Completed match submissions are persisted separately as pending records and retried after refresh; registration is idempotent by `matchId`.

## Architecture

React owns menus, forms, HUD, result dialogs, remote queries, and accessibility. PixiJS owns the arena visuals. Pure systems under `src/game/systems` cover movement, steering, projectiles, damage, collisions, spawning, score, and timing. The current ticker coordinates these systems and publishes only coarse HUD state through the external store. See [ARCHITECTURE.md](ARCHITECTURE.md).

## Delivery Notes

The repository includes the source assets, MSW worker, fixtures, lockfile, unit tests, Playwright tests, and profiling script. Playwright HTML output is generated by `npm run test:e2e`; traces are enabled on first retry. Visual baselines and a public deployment URL still need to be generated/configured for the final submission environment.

## Vercel Deployment

1. Push this repository to GitHub or another Git provider.
2. In Vercel, select **Add New Project** and import the repository.
3. Use these settings:
   - Framework preset: `Vite`
   - Build command: `npm run build`
   - Output directory: `dist`
   - Install command: `npm install`
4. Deploy without private environment variables. MSW serves the demo API from the published bundle.
5. Open the deployment URL and verify Play, Options, Ranking, Match History, mobile layout, and a refresh with a pending registration.
6. Record the final public URL in the delivery submission.

A `vercel.json` is included to make the Vite output directory explicit.
